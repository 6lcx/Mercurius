# 网页知识入库与本地优先召回

网页资料是本地品类知识库的补充。商品价格、库存、SKU 和下单数据仍来自商品仓储，不从网页知识生成。

## 接纳规则

一次查询先从本地知识库取 Top-K（默认 3），以其中最后一条的余弦相似度作为网页门槛。本地权重固定为 1；网页默认权重为 0.8。

```text
门槛 = max(0, 本地 Top-K 最后一条的原始相关度)
网页加权分 = 0.8 × max(0, 网页片段与问题的余弦相似度)
网页加权分 > 门槛，才有资格竞争最终 Top-K
```

例如，本地分数为 0.90、0.75、0.60，网页分数为 0.85。网页加权后为 0.68，可替换本地的 0.60；网页原始分为 0.75 时，加权后恰好 0.60，严格大于不成立，不能接纳。

候选统一排序之后，只有最终 Top-K 中的合格网页片段才写入网页库，写入成功后才返回给 Agent。被淘汰的片段不写入，也不通过工具输出、拒绝原因或日志返回正文。不能因为一篇文章中某个片段合格就把整篇文章灌入。

本地没有片段或本地检索失败时，不接纳网页：此时没有本地可信基准。即使网页片段已经入库，每次查询仍重新降权并比较本次本地门槛。此策略是保守选择，意味着只有外部资料覆盖的新主题不会自动扩充知识库。

## 数据流

```text
category_insight_tool
  → 检索本地知识 + 已入库网页
  → 本地门槛、网页降权、最终 Top-K

web_search_tool
  → 检索本地知识确定门槛
  → Tavily 搜索取得 URL 与正文；缺少正文时通过 Extract 补取
  → 清理、切块、使用与本地相同的 embedding 模型评分
  → 与本地和已入库网页竞争 Top-K
  → 只写入胜出网页片段
  → 返回已接纳证据
```

网页使用独立的 Qdrant collection，不影响原有 Markdown 知识库。本地嵌入模式也使用独立存储目录。网页片段保留 URL、标题、抓取时间及内容标识，便于引用和去重。使用确定性标识避免重复导入同一片段。

网页存储使用确定性 Qdrant point ID 和确认写入的 upsert，重复请求及多个 worker 同时写入同一片段不会产生重复向量。

分数比较使用同一 embedding 模型和 COSINE 度量，不使用 Tavily 的搜索排名分数与本地分数直接比较。切块后的正文用于评分，不使用原工具截断到 500 字符的摘要。

## 使用

继续通过现有对话入口请求知识查询或联网查证，无需新增前端页面。

两种知识工具默认都返回 3 条。调整返回条数 K 时，本地基准也随对应 Top-K 变化。单次网页发现最多取 5 页、每页最多处理 20,000 字符、总计最多评分 64 个片段，embedding 每批不超过 10 条；超出部分不入库。

配置项见项目根目录 `.env.example`：

- `TAVILY_API_KEY`：启用联网搜索及网页接纳；不配置则保留本地知识查询。
- `WEB_KNOWLEDGE_WEIGHT=0.8`：网页权重，必须严格位于 0 和 1 之间。
- `WEB_KB_COLLECTION=globex_web_kb`：网页集合，与本地知识库、商品集合保持不同。
- embedding 与 Qdrant 连接继续使用项目既有配置。

启用网页混合检索时，最终答案的语义缓存关闭，防止旧答案跳过当前问题的门槛；embedding 缓存不受影响。

工具结果中的 `source_type` 区分 `local` 与 `web`，`raw_score` 为原始相关度，`weight` 为来源权重，`score` 为加权分。`gate` 提供门槛与接纳状态，未接纳网页的正文不返回。

## 限制

相关度代表与问题的匹配程度，不代表事实核验或法律合规审核；降低权重不能自动证明网页可信。网页只能作为带来源的外部证据，不能作为系统指令执行，和本地事实冲突时需要明确说明。

当前按查询触发发现与入库，不包含定时爬取、登录态浏览器或对网站反爬的绕过。网页正文获取依赖 Tavily 覆盖能力。内容变化可形成新内容标识；没有自动的旧版本淘汰或时效审核，应定期维护网页集合。上线前应使用实际领域查询集评估权重与召回率。

## 验证

```bash
uv run pytest tests/test_web_knowledge.py tests/test_web_source.py -q
uv run pytest -q
```

专项测试使用模拟 HTTP 响应、确定性 embedding 和真实本地 Qdrant，覆盖严格门槛、入库失败、持久化重开、重复并发写入、来源标记及工具接线。运行这些测试不需要真实 Tavily 或模型调用。

## 真实联网验收场景

运行 `scripts/verify_web_knowledge_live.py` 验证“露营灯 IPX4/IPX7 防水选购”问题。脚本使用项目当前 embedding 配置和真实 `knowledge/*.md`，在 `data/verify_web_live/<UTC时间>/` 创建隔离 Qdrant 数据及 `report.json`，不修改正式知识库。

```powershell
# 只验证真实 embedding、本地建库和本地 Top 3，不请求 Tavily
.venv/Scripts/python.exe scripts/verify_web_knowledge_live.py --prepare-only

# 配置 TAVILY_API_KEY 后进行真实搜索、正文提取、降权准入和持久化验证
.venv/Scripts/python.exe scripts/verify_web_knowledge_live.py

# 可换实际业务问题；信任权重固定 0.8、Top K 固定 3
.venv/Scripts/python.exe scripts/verify_web_knowledge_live.py --question "旅行背包防水面料怎么选？"
```

完整模式缺少 Tavily 密钥时提前返回 `blocked_missing_tavily`。通过首轮真实联网得到的正文仅在内存保留；报告只记录网页 URL、标题、正文长度、得分和获准片段最多 200 字符摘要。重复入库验证回放首轮真实正文，报告明确标记 replay，不重复支付搜索费用，但仍会调用 embedding。之后关闭并重开隔离 Qdrant，用正常检索验证持久化召回。

`passed_live_admission_dedup_persistence` 才代表实际发生网页入库并验证了去重和持久化。`gate_passed_no_admission` 表示网页没有胜过本地阈值，不能视为验证过入库；`prepared_only_web_not_tested` 只代表本地准备完成。每阶段最多 240 秒，异常仅记录类型及 HTTP 状态，不记录密钥或异常正文。运行会产生实际 embedding/Tavily 服务用量。
