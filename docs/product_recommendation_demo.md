# 商品推荐与商品库更新 Demo

## 目标与流程

用户描述用途、预算和偏好，不必知道型号。购买流程只比较真实商品属性，不拿知识文章的相似度作为商品准入门槛。

1. 将需求形成 `ProductSearchSpec`；预算和配送目的地使用结构化参数。
2. 读取现有种子商品及历史新增商品。保留种子数据，不覆盖旧商品。
3. 先过滤硬条件，再评估需求匹配及来源、品牌、销量、质保证据。达到质量阈值的本地候选数量足够时不联网。
4. 本地不足时用 Tavily 查商品详情页；过滤文章，提取带价格、币种和真实购买链接的商品记录。查询只在商品发现适配器转换一次；正文缺少价格时可读取同一商品页面的精确 Product JSON-LD。信息缺失记为未知，不用模型编造。明确露营灯需求时不会因“充电”共同关键词把充电宝当成露营灯。
5. 外部商品使用相同评分规则，再乘默认 0.8 信任折扣，与本次本地候选末位比较；本地不足时允许合格候选补入。
6. 达标候选增量保存到 `external_products.json`。重启后加载，旧商品保留。链接更新属于商品记录，未写入文章知识库。
7. 同一会话及相同需求复用近期推荐，默认有效期 24 小时。入库和展示缓存分开，避免每次询问变化。

## 实际费用与证据边界

跨境商品不因地区被自动排除。应比较同一币种的含运费、税费到手价；网站未给出的费用不能当作零。受预算约束时，缺少完整费用的外部商品不能宣称已满足预算，作为待核验候选呈现。

来源、销量、品牌、质保均需保留网页证据。网页自称官方不等于独立核验，销量不可随意跨平台比较，质保文字不等于已确认在用户所在地有效。现有种子商品是 Demo 数据，仍不具备真实外部购买链接。

## 复现实测

```powershell
$env:PYTHONIOENCODING='utf-8'
& ./.venv/Scripts/python.exe scripts/verify_product_recommendation_live.py --live
```

脚本使用项目配置中的 Tavily 和 embedding，在 `data/verify_product_live/<UTC timestamp>/` 隔离写入测试商品，不修改正式库或种子文件。默认是未知型号的中文露营灯需求，不指定商城。需要 Tavily 凭据；不得把凭据写入报告。

报告 `report.json` 包含：实际候选的链接和证据、评分及准入结果、同一需求再次调用是否免联网且保持结果一致、新商品重启后是否存在、旧商品是否保留。另以同批网页重放 300 元含税费预算场景，避免额外搜索消耗。没有新商品入库时明确报告不完整，不把请求成功当作需求验证通过。

`live_discovery_calls` 统计商品发现服务调用次数；一次发现可能包含主查询和一次不同查询的兜底搜索，因此不是 Tavily 计费请求次数。

这是工具/服务端到端验证，未调用完整 LLM Agent 对话，不证明聊天 token 用量或全部对话行为。
