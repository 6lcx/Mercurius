# 购物需求验收 v1

2026-10-02，首次运行前冻结。24个由Codex编写的合成需求，12个本地选品/约束案例、6个多轮状态/模拟交易案例、6个真实联网选品案例。不是用户调研数据，不称独立人工盲测，也不把重复运行扩充成独立样本。需求基于购物行为与失败风险设计，不以种子商品ID作为推荐题的标准答案；模拟交易题明确使用种子商品。

每例仅运行一次，保持当前业务代码。使用已有真实模型、本地embedding、隔离SQLite与商品库；web模式启用项目现有Tavily发现与页面提取，记录实际返回页面和提取的商家报价，不模拟外部响应。权限条件公开：仅预授权商品查询，创建/取消仍由题目里的用户确认驱动；订单仅为本地模拟，不执行真实购买。预算单位、目标地区由各题给定；没有价格/配送/材质证据时允许澄清或如实报告无法核验，但不能将其计为完成选品。

## 运行前冻结

用例文件包含对话、需求类别、预期交付及3条验收标准。先保存数据与协议SHA256、全部业务与评测源码副本，再发送任何付费请求。没有保留集调参，本轮为首轮诊断性验收；作者与AI复核者相同，无法声称独立评审。不得查看输出后修改题目、删掉失败或降低标准；运行程序错误可修复并另起目录，业务失败保留。确认后的订单用本轮实际订单号，不预设订单号。

## 记录与判断

- 每轮保存输入、完整回复、工具invoke/result、Agent状态、订单/库存/偏好快照、当前完整商品证据。联网调用保存查询、取得时间、URL、正文、哈希、失败；商家结构化报价另存。网页提取证明当时观察到的商家声明，不证明商家可靠或未来价格不变。
- 自动检查只判运行完整性、未授权写入、无证据商品ID、工具和网页调用数量；不能把自动检查全部通过称为任务验收通过。
- 每例3条逐项验收由Codex读取原始记录后复核，结论为pass/fail/insufficient_evidence，必须附具体说明和带JSON定位路径的证据。判定文件保存记录SHA256、原文摘录；程序验证引用真实存在。事实真伪没有充分证据时标insufficient_evidence，不能默认通过。
- 单独记录delivery=fulfilled/partial/unfulfilled。合格的澄清、拒绝伪造、能力边界说明可以通过相应验收项，但delivery仍可能未完成。必须报告两者，不只展示好看的通过比例。
- 所有回复供用户再审阅，human_reviewed=false；主观推荐质量仍需独立评审。这轮AI验收不是人类满意度。
- 汇总逐题验收、交付比例、失败类型、mean/median/P90、模型真实usage及缺失字段、联网覆盖、实际网页商品交付。24题为设计覆盖样本，不给生产泛化或历史优化效果结论。

## 范围与限制

不修改app业务源码；不修复发现的业务问题后覆盖本轮分数。项目允许本地充足时不联网；若题目明确要网页链接而系统没有联网/没有找到可核验候选，按交付不足记录。未覆盖真实支付、履约、真人满意度和人工定位时间。网页数据漂移、来源访问失败、动态价格均保留到证据中。

命令：`.\.venv\Scripts\python.exe -B -m scripts.benchmark.shopping_acceptance --output output/acceptance/shopping-v1`。单例180秒、模型调用最多300次、联网search最多40次；外部不可用不无限重试。验收记录由独立的review.json写入，不改变原始observations.jsonl。
